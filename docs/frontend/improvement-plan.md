# Frontend Improvement Plan — читаемость, адаптивность, UI/UX

Приоритизированный план улучшений Mini App. Основан на аудите текущего кода
(после перевода `ui/` на shadcn-паттерн) и скриншотах реальных экранов.
Оценки: S — до часа, M — до полудня, L — день+.

## Этап 1 — читаемость и консистентность (быстрые победы)

### 1.1 Типографическая шкала (M)
Сейчас по фичам рассыпаны произвольные размеры: `text-[10px]…text-[18px]`,
десятки `text-[11px]/text-[12px]` (матрица, таблица, детали заказа, layout).
Ввести шкалу из 4 ступеней как утилиты/константы (caption 12, body 13,
emphasis 14, title 16/18), убрать 10px полностью (нечитаемо на телефоне),
11px оставить только для uppercase-надзаголовков. Файлы: все `features/`,
сверять по скриншотам.

### 1.2 Финиш миграции на токены (M)
Фичи всё ещё красятся напрямую `stone-*` (это работает — taupe-рампа
сохранена), а `ui/` уже на семантических токенах. Договориться: **новый код —
только токены**; старый мигрировать оппортунистически. Отдельно вычистить
**инлайновые hex** в `OrderDetails.jsx` (`changeColor`/`changeBackground`
возвращают `#1f9d55`, `#fde8e8`, …) — заменить на Tailwind-классы или токены.

### 1.3 Единый словарь сокращений (S)
«N поз.», «6 заяв.», «позиций: 52», «отклонений: 3» — привести к одному
стилю (предложение: везде полные слова с русской плюрализацией — хелпер
`plural(n, 'позиция', 'позиции', 'позиций')` в `lib/format.js`).

### 1.4 Контраст (S)
Проверить пары на WCAG AA: `text-stone-400` на белом (плейсхолдеры, точки
пустых ячеек таблицы), `muted-foreground` на `muted`. Поднять до
`stone-500`/`stone-600` там, где это текст, а не декорация.

### 1.5 Перенос vs троеточие (S)
Названия блюд то `truncate` (журнал), то `break-words` (таблица, лист).
Правило: **данные не троеточим** (имена блюд, номера заказов — переносим),
троеточить можно только вспомогательные строки с `title=`.

## Этап 2 — адаптивность

### 2.1 Safe areas и viewport Mini App (S)
`index.html` не имеет `viewport-fit=cover`, нижняя навигация не учитывает
home-indicator iPhone. Добавить `viewport-fit=cover` и
`padding-bottom: env(safe-area-inset-bottom)` к фикс-навигации и нижним
кнопкам форм; вызвать `Telegram.WebApp.expand()` при старте.

### 2.2 Матрица на телефоне (M)
Три колонки магазинов на 390px — карточки сжаты до предела. Варианты:
(а) горизонтальный скролл колонок со snap-точками и липкой полосой дат;
(б) аккордеон по магазинам внутри полосы даты. Прототипировать (а) — он
сохраняет ментальную модель «колонка = магазин».

### 2.3 Админ-таблицы на телефоне (M)
`AdminUsers`/`AdminDishes` — широкие таблицы в `overflow-x-auto` без
заморозки: на телефоне имя пользователя уезжает вместе со скроллом.
Применить паттерн из `/orders/table`: липкая первая колонка + липкая шапка;
либо карточный layout `< sm`.

### 2.4 Нижняя навигация админа (S)
6 пунктов на 320px — подписи «Отработки»/«Таблица» упираются. Спрятать
подписи (`< 360px` только иконки) или объединить «Люди/Блюда» в «Админ».

### 2.5 Планшет/десктоп-брейкпоинты (S)
Почти всё живёт на `sm:`; на `md/lg` — растянутые панели. Пройтись по
ключевым экранам: ограничить ширину форм (`max-w-2xl`), у деталей заказа
двухколоночный meta-grid на `md+`.

## Этап 3 — UX-механики

### 3.1 Skeleton-состояния загрузки (M)
Сейчас загрузка — это пустота или замершие кнопки. Добавить `ui/Skeleton`
(shadcn) и применить в матрице, таблице, журнале, деталях заказа: серые
плейсхолдеры вместо прыжка контента.

### 3.2 Toast-уведомления об успехе (M)
Сохранения проходят молча (отработка, заказ, админ-правки). Обернуть Radix
Toast в `ui/Toast` + hook `useToast`; показывать «Отработка №N сохранена»,
«Заказ создан» с переходом. Ошибки остаются в `ErrorBanner` (они требуют
контекста места).

### 3.3 Кнопка с прогрессом (S)
`Button` не показывает занятость — только `disabled`. Добавить проп
`loading` (спиннер + disabled), применить во всех submit-действиях.

### 3.4 PromptDialog для сброса пароля (S)
Последний нативный диалог — `window.prompt` в `AdminUsers.onResetPassword`.
Сделать `ui/PromptDialog` (Dialog + InputField) с кнопкой «Сгенерировать»
и копированием результата.

### 3.5 Guard несохранённых правок (M)
Лист отработки и редактор заказа теряют ввод при уходе со страницы.
Отслеживать dirty-состояние и спрашивать через `ConfirmDialog` при
навигации (перехват в `navigate`).

### 3.6 Пустые состояния с действием (S)
`EmptyState` — только текст. Добавить слот `action`: «Заказов нет» +
кнопка «Создать заказ» / «Открыть матрицу».

### 3.7 Память фильтров (S)
Выбор категории (матрица, таблица) и окно дат сбрасываются на перезагрузке.
Сохранять в `localStorage` (ключи `bakery.ui.*`).

### 3.8 Иконки-кнопки и клавиатура (S)
Пройтись по icon-only кнопкам (звёздочка избранного, закрытие) — у всех
должен быть `aria-label`; чипы категорий — фокусируемы (уже кнопки, ок),
проверить порядок табуляции в модалках.

## Этап 4 — стратегическое

### 4.1 Тёмная тема из Telegram (L)
Токены это разблокировали: определить `.dark`-набор (тёплые тёмные тона),
включать по `Telegram.WebApp.colorScheme` + `prefers-color-scheme`.
Категорийные цвета и сегодня/завтра потребуют своих тёмных вариантов.

### 4.2 Виртуализация длинных списков (L)
Таблица блюд (76+ строк × 8 дат) и каталог админки рендерятся целиком.
Пока приемлемо; при росте каталога — `@tanstack/react-virtual` внутри
скролл-контейнера таблицы.

### 4.3 Разгрузка OrdersPage (M)
Оркестратор ~560 строк: маршрутизация, выбор, монитор, продакшн, редактор.
Вынести хуки `useOrdersData`, `useSelection`, `useMonitor` — упростит и
guard из 3.5.

## Порядок работ

1. Этап 1 целиком + 2.1 + 3.3 + 3.4 (день) — заметный прирост качества без
   риска.
2. Этап 3: 3.1, 3.2, 3.6, 3.7 (день) — «живость» интерфейса.
3. Этап 2: 2.2, 2.3 (день) — мобильные сценарии пекаря и админа.
4. Этап 4 — по мере надобности; тёмную тему делать только после миграции
   фич на токены (1.2), иначе придётся красить дважды.

Каждый пункт закрывается по циклу из `docs/adding-features.md`
(lint/build/typecheck + скриншот-проверка Playwright на 390px и 1280px).
